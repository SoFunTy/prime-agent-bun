- `prime-agent` now always runs the Bun kernel and its kernel tool is `bun_repl`; there is no Python fallback, so an install without Bun fails the kernel start with install guidance. Set `PRIME_AGENT_KERNEL_BUN` or `PRIME_AGENT_BUN_RUNTIME_DIR` to override the binary or the runtime payload.
- Added the Bun kernel runtime (`prime-agent-bun-runtime`): REPL protocol v3, the `rlm` API, executable JavaScript skills, a dependency-free MCP client, the `[bash-done]` completion lane, and a `kernel-bun` prompt layer that documents every call shape in JavaScript/TypeScript.
- Cells accept JavaScript **and** TypeScript (types are erased), support `require`, every static `import` form, and every control-flow shape (`if`/`else`, `try`/`catch`/`finally`, `do`/`while`), and return their trailing expression. Top-level bindings survive automatic compaction, and skill documentation is JavaScript throughout.
- Kernel-facing wording follows the running kernel: the tool name and description, busy prompts, restart and restore notices, the cell-timeout hint, the skills inventory, the compaction note, the cell-card language label, and `--help` never claim Python in a Bun session. Wire and durable identifiers (`<python_import>`, `[python-state]`, `<ipython_kernel_reset>`, `pythonCellTimeoutMs`) are unchanged.
